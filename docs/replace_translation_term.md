# 訳語の機械置換の手順

訳語・用語リスト (`docs/translation_terms.md`) で決めた訳語を, 既存の対訳に
さかのぼって当てはめるときの手順をまとめる. 旧訳語の文字列を新訳語の
文字列へ一括で置き換え, 置換では直らない箇所を洗い出して手作業に回す
ところまでを扱う. 文語漢語や古語の置換で崩れやすい形は
`docs/plain_terms.md` の「機械置換の落とし穴」も参照する.

## この手順が向く置換

- 旧訳語が 1 つの決まった文字列で, 活用しない名詞である
- 旧訳語と原語がほぼ 1 対 1 で対応している
- 置換しても前後の助詞や語尾を変える必要がない

次のものはこの手順だけでは済まない.

- 和語動詞や「〜する」以外の活用をもつ語. 活用形ごとに崩れるので
  `docs/plain_terms.md` の落とし穴に従って活用形を全部挙げて確かめる
- 原語によって訳し分ける語 (attha など). 文脈を読んで個別に判断する
- 訳の内容に踏み込む直し. 置換ではなく改訂として扱う

## 全体の流れ

1. 旧訳語と変形, 原語の語形を洗い出す
2. 置換する文字列と対象ファイルを決める
3. 訳語と原語の対応をブロック単位で突き合わせる
4. 置換で崩れる箇所と, 置換にかからず残る箇所を見積もる
5. 1 ファイルで試す
6. 全対象ファイルを置換し, メタ情報を更新する
7. 検証する
8. 別の目で文脈を確かめる (任意)
9. コミットして PR にする
10. 残った箇所を手作業で直す

1 から 4 まではファイルを変更しない. ここで方針をユーザに示し, 判断が要る
点を決めてから 5 以降に進む.

## 1. 洗い出し

次の 3 つを数える.

- 旧訳語と新訳語それぞれの件数. ファイルごとの内訳も見る. 同じファイルの
  中で新旧が混在していることがある (チャンクごとに生成時期が違うため)
- 旧訳語に似た変形. 語尾のない形, 字の順が違う形, 言い換えだけの形など
- 原語の語形. 格変化, 複合語の前分・後分, 否定の a- が付いた形を含める

日本語の文字列を数えるときの注意:

- `git grep -o` や `grep -o` に日本語の文字クラス (`[者り]` など) を渡すと,
  ロケールによってはバイト単位で切られて結果が壊れる. 文字単位の集計は
  UTF-8 のロケールを指定したスクリプトで行う
- macOS の `sort` と `uniq` は, UTF-8 のロケールでは異なる日本語の行を
  同じものとして数えることがある. 集計では `LC_ALL=C sort | LC_ALL=C uniq -c`
  とする
- `ruby -e` に日本語を含むコードを渡すときは `LC_ALL=en_US.UTF-8` などを
  指定する. 指定がないと invalid multibyte character で止まる

## 2. 置換する文字列と対象を決める

置換する文字列は, 別の語を巻き込まない最も狭い形にする.

- 旧訳語が別の語の訳の一部と重なる場合は, 重ならないところまで含めて
  照合する. 例: 正等覚者 (sammāsambuddha) を置換するとき, `正等覚` で
  照合すると sammāsambodhi の訳「正等覚」まで変わる. `正等覚者` で照合する
- 基準にない関連語 (上の例の sammāsambodhi) は触らない. 訳語を決めるのは
  ユーザであり, 置換のついでに決めない

対象から外すファイル:

- 凍結ファイル (`_v1`). 行番号で参照されるため変更しない
- 履歴ファイル (`_history.md`) の過去の記述
- 基準そのものを書いたファイル. `docs/translation_terms.md` と
  `system_prompt_no_paraphrase.md` の「旧訳語は使わない」という行は,
  旧訳語の文字列を含むが置換してはいけない

ユーザに確認するもの:

- 別モデルによる対訳 (`_fable`, `_opus` などの接尾辞のファイル) を含めるか
- 調査ノート (`notes/`) や用例集に旧訳語がある場合の扱い

## 3. 訳語と原語の対応を突き合わせる

対訳を「番号付きのパーリ再掲行から次の番号行の前まで」のブロックに分け,
ブロックごとに次の 3 種類を拾う.

- 旧訳語があるのに, 同じブロックに原語がない. 別の原語の訳や, 説明の中の
  補足として旧訳語が使われている箇所. 置換してよいかを 1 件ずつ見る
- 原語があるのに, 旧訳語も新訳語もない. 訳語を使わず言い換えだけで訳して
  いる箇所. 置換にはかからない
- 同じブロックに新旧が両方ある. 併記や書きかけの箇所

```ruby
# 対訳をブロックに分け, 訳語と原語の対応を調べる
# 使い方: 一時ファイルに保存し, ruby <保存したファイル> <md ファイル...>
OLD = "正等覚者"
NEW = "正自覚者"
PALI = /samm[āa]-?sambuddh/i

ARGV.each do |f|
  blocks = []
  File.read(f, encoding: "UTF-8").lines.each_with_index do |l, i|
    blocks << { start: i + 1, lines: [] } if l =~ /\A\d+\. / || l =~ /\A#/ || blocks.empty?
    blocks.last[:lines] << l
  end
  blocks.each do |b|
    text = b[:lines].join
    old = text.include?(OLD)
    new = text.include?(NEW)
    pali = text =~ PALI
    puts "#{f}:#{b[:start]} 旧訳語あり, 原語なし" if old && !pali
    puts "#{f}:#{b[:start]} 原語あり, 訳語なし" if pali && !old && !new && text.include?("→")
    puts "#{f}:#{b[:start]} 新旧が同居" if old && new
  end
end
```

## 4. 崩れる箇所と残る箇所を見積もる

置換の前に, 次の型がどこに何件あるかを数えておく.

- 自己重複. 旧訳語と新訳語を併記している行 (「旧、新」「旧（新）」など) は,
  置換すると同じ語が 2 つ並ぶ. 置換のあとで重複を除く
- 語源説明との食い違い. 語釈行が訳語と語を砕いた言い換えを並べている場合,
  言い換えは旧訳語の字に沿って書かれている. 訳語だけを置換すると, 新訳語の
  字と言い換えが対応しなくなる. 例: 「正しく完全に覚った者、正等覚者」は
  等 と「完全に」が対応していたが, 正自覚者 に置換すると 自 に当たる説明が
  なくなる
- 言い換えだけで訳している箇所. 3 で拾った「原語あり, 訳語なし」のブロック.
  語釈行だけ直すと文訳と合わなくなるので, 文訳も合わせて見る
- 基準にない関連語が旧い字のまま残る箇所. 同じ文に新旧の字が並ぶことが
  ある. 誤りではないので, 関連語の訳語が決まるまでそのままにする

自己重複は置換と同時に直す. それ以外は機械置換の範囲を超えるので, 一覧に
して 10 の手作業に回す.

## 5. 1 ファイルで試す

新旧が混在しているファイルや件数の多いファイルを 1 つ選び, 6 と 7 を
そのファイルだけで行う. 結果をユーザに見せてから全体に広げる.

## 6. 置換とメタ情報の更新

```ruby
# 旧訳語を新訳語に置換し, frontmatter の updated を当日にする
# 使い方: 一時ファイルに保存し, ruby <保存したファイル> <md ファイル...>
OLD = "正等覚者"
NEW = "正自覚者"
TODAY = "2026/11/23"

ARGV.each do |f|
  s = File.read(f, encoding: "UTF-8")
  n = s.scan(OLD).size
  next if n.zero?
  s = s.gsub(OLD, NEW)
  m = s.match(/\A---\n(.*?\n)---\n/m) or raise "frontmatter がない: #{f}"
  fm = m[1]
  raise "updated がない: #{f}" unless fm =~ /^updated: /
  s = "---\n" + fm.sub(/^updated: .*$/, "updated: #{TODAY}") + "---\n" + m.post_match
  File.write(f, s)
  puts "#{n}\t#{f}"
end
```

メタ情報の扱い:

- frontmatter の `updated`: 置換が入ったファイルだけ作業日に更新する.
  `generated` と `source` は変えない
- `### Meta` ブロック: 変えない. 節ごとの生成日と生成モデルの記録であり,
  置換は生成ではないので, 置換した日やモデルを足さない
- `status: incomplete` の行: 触らない
- 既存の `_history.md`: 対応する対訳に置換が入ったら項目を追記する.
  対象は節番号と原語で書き, 行番号は書かない. 件数, 自己重複など手で
  直した箇所, 変えなかった関連語, 検証の内容を書く
- `_history.md` のないファイル: 新設するかどうかをユーザに確認する
- `docs/translation_terms.md`: 基準は置換の前に書かれている前提. 置換の
  ついでに節を書き換えたり項目を移したりしない

## 7. 検証

置換前 (HEAD) と行単位で突き合わせ, 次を確かめる.

- 行数が変わっていない
- 変更行は, `updated` の行と手で直した行を除き, すべて「旧訳語 → 新訳語」
  の差だけである
- 変更行は語釈行 (`*` で始まる行) と文訳 (`→` で始まる行) だけで, 番号
  付きのパーリ再掲行と原文ブロックに変更がない

```ruby
# 変更行を HEAD と突き合わせ, 置換だけの差かを確かめる
# 使い方: 一時ファイルに保存し, git diff --name-only -z | xargs -0 ruby <保存したファイル>
OLD = "正等覚者"
NEW = "正自覚者"

kinds = Hash.new(0)
ARGV.each do |f|
  a = `git show HEAD:#{f}`.force_encoding("UTF-8").lines
  b = File.read(f, encoding: "UTF-8").lines
  raise "行数が違う: #{f}" unless a.size == b.size
  a.zip(b).each_with_index do |(x, y), i|
    next if x == y
    next kinds["updated"] += 1 if x.start_with?("updated:") && i < 6
    unless x.gsub(OLD, NEW) == y
      puts "置換以外の差: #{f}:#{i + 1}"
      next
    end
    kind = x.start_with?("→") ? "文訳" : x =~ /\A\s*\* / ? "語釈行" : "その他"
    kinds[kind] += 1
    puts "語釈行・文訳以外: #{f}:#{i + 1}" if kind == "その他"
  end
end
kinds.each { |k, v| puts "#{k}: #{v}" }
```

そのうえで次を行う.

- 置換した全箇所を, 前後 10 字程度の文脈つきで読む. 変更行を数えるだけで
  済ませない. 同じ文脈はまとめて件数にしてよい
- 置換後に旧訳語を grep し, 残っているのが対象外のファイルだけであることを
  確かめる
- 重複形を grep する. 「新、新」「新・新」「新（新）」「新(新)」など, 括弧や
  読点をはさむ形も含める
- 生成時の作業ディレクトリに正本テキストが残っているファイルは,
  `scripts/verify_taiyaku.rb` を置換の前後で実行し, 出力が同じであることを
  確かめる. 残っていないファイルは, パーリ再掲行が変わっていないことの
  確認で代える

## 8. 別の目で文脈を確かめる (任意)

件数が多いときは, 置換をしたのとは別のセッションやサブエージェントに
全箇所を読ませる. 依頼には, 対象のコミット, 済ませた機械的な確認, すでに
把握していて報告に入れなくてよい点, 読み取り専用であることを書く.
見てもらう観点:

1. そのブロックの原語が対象の語ではなく, 新訳語が原文に合わない箇所
2. 旧訳語が訳語としてではなく語そのものへの言及だった箇所 (漢訳語や他の
   訳の紹介, 訳語についての訳注など). 置換で文意が変わっていないか
3. 註釈書や復註が対象の語の語義を説明している箇所で, 置換後の訳文が
   説明として筋が通らなくなっていないか
4. 置換後の日本語が不自然になった箇所, 同じブロックの中で訳語の扱いが
   食い違っている箇所
5. そのほか, 置換が原因で読み手が誤解しそうな箇所

届いた報告は, 指摘箇所をファイルで確かめてからユーザに伝える.

## 9. コミットと PR

- コミットと PR はユーザの指示を待って行う
- 置換とメタ情報の更新, 履歴ファイルへの追記は 1 つのコミットにまとめる
- PR の本文には, 置換の方針, 変更内容, 対象外にしたもの, 検証の内容,
  この PR で直していないことを書く

## 10. 残った箇所の手作業

4 で一覧にした箇所を, 置換が済んでから手作業で直す. 置換と同じコミットに
混ぜない.

- 語釈行の言い換えは, 訳語と言い換えの形をユーザと決めてから揃える.
  例: `sammāsambuddha = 「正自覚者、正しく自ら覚った者」`
- 見出しが格変化した形の語釈行は, 訳の末尾の助詞を残す
- 言い換えだけで訳している箇所は, 語釈行と文訳を合わせて直す
- 註釈書がその語そのものを説明している箇所の引用は, 説明の中身に合わせて
  書かれているので, 形を揃える対象にしない
