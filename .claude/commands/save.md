# 調査ノートの保存

このプロジェクトでの調査結果を `notes/` 配下の markdown にまとめる.

`notes/` は `.gitignore` に含まれず, リポジトリは GitHub の公開リモートを
持つ. したがって書いたものはコミットされ第三者の目に触れる前提で扱う.

## 目的と守備範囲

ユーザが疑問に思ったこと, 知りたかったことを議論し, その答えを後日参照
できる形で残すことが目的である. ノートの中心は疑問とその答えであり, 出典
や前提はそれを裏づける材料として扱う.

書く内容と構成に迷ったときは「この記述は疑問に答えるために要るか」で
判断する. 資料を並べただけのものはノートとして成立しない.

保存先の使い分け:

- `notes/` — 疑問と答え. 語義の検討, 訳語選定の根拠, 註釈の読み比べ,
  原典の構造調査, 実装の挙動確認など
- `docs/` — 手順書. 「こう作業する」を書いたもの. 既定で gitignore され,
  公開は個別に opt-in する (docs/publish_doc.md)
- 対訳本体 (`mn/`, `dn/` など) — 訳文そのもの. ノートから訳文を書き換え
  にいかない

対訳の新規生成は taiyaku スキルが担当する. このコマンドではコード変更や
コミットを行わない.

調査の結果として対訳を直すべき箇所が見つかった場合は, ノートにはその
指摘を書くにとどめ, 改訂の実行はユーザの指示を待つ.

## 手順 1: 保存対象の決定

引数: $ARGUMENTS

上の引数の有無と会話履歴の組み合わせで判断する.

- 引数なし + 会話履歴あり: これまでの会話全体を振り返って内容をまとめる
- 引数なし + 会話履歴なし: 何を保存すべきか不明なため, ユーザに確認する
- 引数あり + 会話履歴あり: 会話の内容をベースにしつつ, 引数の指示を反映
  させる (「○○の章を追加して」「□□について詳しく書いて」「△△の観点で
  まとめ直して」など, 会話内容への加工・追記・調整指示として解釈する.
  必要なら追加調査も行う)
- 引数あり + 会話履歴なし: 引数を独立したテーマとして扱い, 調査してから
  まとめる

## 手順 2: 事実の裏取り

書く前に, 主張の根拠を実データで確認する. 記憶や推測で書かない.

- パーリ語の語義は DOP, CPD, PTSD の順で引く. DOP と CPD には未刊行の範囲
  があるため, そこは全アルファベットを収録する PTSD で補う. DPD は参考
  程度に留め, 語義の根拠としては使わない
- 原典テキストの内容は CSCD や PTS の全文検索で確認する. 手元に VRI XML
  がある場合は `_tmp/` のファイルを直接読んで数え上げる方が確実
- 既存の訳語・訳文を論じる場合は対訳 md 本体を読んで確認する. 記憶で
  「こう訳してあったはず」と書かない
- 件数・出現数・分布などの数値は実際に集計した結果を書く
- スクリプトの挙動は `scripts/` の該当コードを読んで確認する
- 訳語の方針は CLAUDE.md, `docs/plain_terms.md`, `docs/translation_terms.md`
  に既存の決定がある. 既決事項と新しい提案を混ぜない
- 伝承や二次情報を書く場合は「CSCD に無い」と「存在しない」のように,
  確認できた範囲と一般的な主張を明確に区別する

裏取りに使ったツールはあくまで手段であり, ノートには書かない (手順 5).

## 手順 3: ファイル名の決定

- 内容からトピックを推測し, 英語のケバブケースで付ける
- 必ずベースとなる対象名を prefix にする. このプロジェクトでの例:
  - `term-` 訳語・語義の検討 (例 `term-yathattha.md`)
  - `grammar-` 語形・格・複合語などの文法的な分析
  - `attha-` 註釈・復註の読みや註釈間の異同
  - `mn-` `dn-` `sn-` `vin-` `dhp-` `ja-` `patis-` `vism-` 特定テキストの
    読解メモ. 経番号を含めるときはゼロ埋め (例 `mn-043-vedalla.md`)
  - `cscd-` VRI/CSCD のテキストや XML 構造
  - `taiyaku-` 対訳の作成・改訂の運用に関する知見
  - `script-` `site-` スクリプトやサイト生成の実装調査
- 区切り文字はハイフンで統一する. 拡張子は `.md`
- 対訳本体のファイル名規則 (`mn_043.md` のアンダースコア) とは別系統で
  あることに注意する. ノートはハイフン
- 例: `term-assasa-passasa.md`, `cscd-tika-heading-structure.md`

## 手順 4: 内容の整理

疑問 -> 答え -> 根拠の順に構成する. これは文書全体だけでなく各節にも適用
する. 前提条件, 出典, 定義といった材料から書き始めない.

### 全体の構成

- タイトルは議論した疑問の範囲を覆うものにする. 複数の論点を扱ったのに
  そのうち一つだけを切り出したタイトルにしない
- 冒頭に `# タイトル` を置き, 続けて疑問への答えを書く. 読み始めてすぐに
  何の話でどういう結論かが分かる状態にする
- 節は疑問ごとに切る. 各節は「主張 -> 根拠 -> 留保」の順で書く
- 節を否定文や反論から書き始めない.「X ではない」と書くなら, なぜ X と
  読めてしまうのかを先に一文で示す. 否定される側の見方が会話の中にしか
  ない状態にしない
- 出典, 参考 URL, 調査対象ファイルの一覧は末尾にまとめる. 冒頭や各節の
  前置きに置かない
- 答えるのに要らない記述は落とす. 網羅は目的ではない

### 書き方

- 「原文が言っていること」「註釈が読み込んでいること」「自分の推論」を
  区別して書く. 註釈の解釈を原文の意味として書かない. 区別は文中の一言で
  済ませず, 節の冒頭で出所を示す
- 註釈が複数の説を並べている場合は, それが註の記述であること自体を明示
  したうえで, `vadanti` (他師の説), `atha vā … veditabbaṃ` (註自身の別案)
  のように註の中での扱いの差も書く
- プロジェクトの翻訳方針と資料の記述が食い違う場合は, どちらかに寄せて
  書かず両方を記し, 方針がどちらを採っているかを明示する
  (例: assāsa を「出息」とする方針と, これを「入息」とする資料の併存)
- 訳語の候補を比較した場合は, 却下した案とその理由も残す. 後から同じ
  検討を繰り返さないために要る
- 確認できていない範囲があれば, 末尾にその旨を明記する
- 主要なトピックは見出し・表・リストで構成する

### 表記

- パーリ語は IAST のダイアクリティクスを正確に保つ (ṃ ā ī ū ṭ ḍ ṇ ḷ ñ ṅ)
- 原文引用はコードブロックに入れ, 表記を改変しない
- 対訳 md の箇所を指すときはセクション番号 (VRI 番号) と原語で示す.
  行番号は使わない (改訂で容易にずれるため)
- 「段落」は VRI 番号段落 (`##` 見出し単位) を指す. XML の `p` 要素と
  混同しない場合は, どちらの意味かを書き添える
- CSCD のファイルは `s0202m.mul0.xml` のように corpus 内の相対名で示す
- 集計を行った場合は「何を対象に何を数えたか」を書く
- 作業の呼び分けを守る. 訳文を直すのが「改訂」, 問題箇所を指摘するのが
  「校閲」.「校訂」は原典の本文批判にのみ使う
- 日付は「2026-08-04」のように絶対日付で書く.「昨日」「先週」と書かない
- 会話を保存する場合は対話のやり取りを省く. ただし疑問そのものはノートの
  骨格として残す

## 手順 5: 公開を前提とした書き方

- 内部的なツール名を書かない. MCP サーバ名やツール名 (`lookup_dpd`,
  `search_cscd_texts` など) はノートに一切登場させない. 参照した資料は
  CSCD, PTS, DPD, PTSD, DOP, CPD のように, 資料そのものの名前で書く
- ローカル絶対パス (`/Users/...`) を書かない. リポジトリ相対パスにする
- グローバル個人設定 (`~/.claude/CLAUDE.md` など) の内容に言及しない
- 個人情報, 認証情報, 未公開の URL を含めない
- `docs/` 配下の未追跡ファイルを参照しない. 参照が要る場合はその内容を
  本文に展開するか, 公開済みファイル (docs/publish_doc.md の一覧) に
  限る
- 会話固有の文脈 (依頼の経緯, ユーザとのやり取り) に依存しない, 単体で
  読める文章にする
- 内部メモとして残したい場合はユーザに確認してから判断する

## 手順 6: 書き出し

- 保存先は `notes/`. 存在しない場合は作成する
- 先頭に YAML frontmatter を置く:

  ```
  ---
  generated: 2026/08/04
  updated: 2026/08/04
  models: Claude Opus 5
  ---
  ```

  - `generated` は初回保存日, `updated` は最終改訂日. 日付は対訳の
    frontmatter と同じ `YYYY/MM/DD` 形式 (本文中の日付表記 `2026-08-04`
    とは別)
  - `models` は作成にかかわったモデル名をカンマ区切りで 1 行に並べる.
    改訂に別モデルが関わったら置き換えずに追記する
  - 対訳と違い `source` は置かない
- 既存ノートを改訂した場合は `updated` を当日の日付に更新する
- 同名ファイルが既に存在する場合は上書きせず, ユーザに確認する
- 保存後, リポジトリ相対のファイルパスを markdown リンクで示し, 章構成と
  公開前提で調整した点を簡潔に報告する
- コミットとステージは行わない. ユーザの明示的な指示を待つ

## 注意事項

- 絵文字は使わない
- 日本語で記述する. 句読点は「、」「。」を使う (対訳本体と同じ表記)
- 英単語と日本語の間には空白を入れる
- 「完璧」「素晴らしい」といった過度な肯定表現や断定的な表現を避ける
