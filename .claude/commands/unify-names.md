# 対訳の人名の表記揺れの修正

既存の対訳 md で, 同じ人物の名前が複数の表記で書かれている箇所 (例: korabya
が コーラビヤ / コーラヴィヤ / コーラッバ) を洗い出し, 修正候補として報告する.
まず調査と候補の提示までを行い, 修正はユーザが統一先を決めてから行う.
対訳の再生成や訳の内容の改訂ではない.

引数: $ARGUMENTS

## 手順 1: 対象の決定

- 経の番号 (「MN 82」など) が与えられたら, 経・註釈・復註の対訳のうち
  存在するものを対象にする (例 `mn/mn_082.md`, `mn/mn_attha_082.md`,
  `mn/mn_tika_082.md`). 同じ人物が経と註の両方に出るので, ファイルを
  またいで表記を比べる
- ファイルのパスが与えられたら, そのファイルだけを対象にする
- 「経だけ」などの指示があれば, それに従って対象を絞る
- 次のファイルは指示がない限り対象から外す: 凍結ファイル (`_v1`),
  履歴ファイル (`_history`), 作業工程のファイル (`_check`, `_reviewed`),
  別モデル版や比較用のファイル (`_fable`, `_opus`, `_gemini`, `_noctx`
  などの接尾辞)
- 特定できなければユーザに確認する

## 手順 2: 調査 (ファイルは変更しない)

### カタカナ語の集計

対象ファイルごとにカタカナ語を数える. `grep -o` に日本語の文字クラスを
渡すとロケールによって結果が壊れるため, UTF-8 を指定したスクリプトで行う.

```sh
LC_ALL=en_US.UTF-8 ruby -e 'ARGV.each { |f| h = Hash.new(0); File.read(f, encoding: "UTF-8").scan(/[ァ-ヴー]{2,}/) { h[$&] += 1 }; puts "== #{f}"; h.sort_by { |k, v| [-v, k] }.each { |k, v| puts "#{v}\t#{k}" } }' <md ファイル...>
```

一覧から人名を拾い, 似た表記 (ビ/ヴィ, バ/ヴァ, 長音や促音の有無, 語尾の
違いなど) が並んでいないかを見る. 文法用語 (アオリスト など) や一般の
外来語は除く.

### 原語との突き合わせ

人名ごとに, 原語のすべての語形 (格変化, 複合語の前分, 呼格) を対象
ファイルで検索し, 語釈行と文訳でどの表記が使われているかを確かめる.
カタカナの字面が離れていて集計では似て見えない揺れ (コーラヴィヤ と
コーラッバ など) は, 原語の側から探して見つける.

### 漢訳名

人名の語釈行と文訳で, 漢訳名の使い方を確かめる (帝釈, 梵天, 舎利弗,
目連, 阿難 など).

- カタカナ名を主にして漢訳名を括弧で添えた形 (「サッカ（帝釈天）」) は
  人名では許容する. 候補にしない
- 漢訳名だけで書いた箇所 (カタカナ名がない) は候補にする

CLAUDE.md と `docs/translation_terms.md` の「漢訳名は使わない」は, 対訳や
ノートを新しく書くときの基準である. 既存の対訳を直すこのコマンドでは,
上の扱いに従う.

### 揺れとして扱わないもの

次のものは表記の揺れではないので, 候補にしない.

- 原語の形が違う語. 註釈が名前の由来を別の語で説明している箇所など
  (例: thullakoṭṭhika の説明に出る thullakoṭṭha を トゥッラコッタ と
  音写した箇所)
- 同じ語を人名ではなく普通名詞として訳した箇所 (例: 偈の migavo を
  「猟師」と訳した箇所と, 人名の ミガヴァ)
- 「(人名)」「（園の名）」など, 名前の後ろに付けた補足の違い

### 候補にせず報告だけするもの

- 人名以外の固有名詞 (地名, 園林名, 経名など) の揺れや漢訳名. 人名と
  分けて報告する
- 同じ人物の役目や肩書きの訳の違い (例: 経では「猟師」, 註釈では
  「園丁」). 訳の内容の判断なので, このコマンドでは直さない
- 調査の途中で気づいた, 人名と関係のない用語の問題

## 手順 3: 修正候補の報告

人名ごとに次を書く.

- 原語
- 表記ごとの件数と, 出てくるファイルと節 (§ 番号). 語釈行と文訳の
  どちらにあるかも書く
- 統一先の案と理由. 次の順で考える
  1. `docs/translation_terms.md` に決まった表記があれば, それにする
  2. なければ, 対象ファイル全体で多く使われている表記を基本にする
  3. 多い表記が原語の綴り (b と v, 長母音, 重子音など) に合わない場合や,
     件数が拮抗している場合は, そのことを書いたうえで案を出す

揺れのなかった人名は, 名前を並べて「揺れなし」とまとめる. 手順 2 の
「候補にせず報告だけするもの」は別の見出しで書く.

報告したら止まり, ユーザが統一先を決めるのを待つ. ファイルは変更しない.

## 手順 4: 修正 (ユーザが統一先を決めたあと)

ユーザが指示した人名と統一先だけを直す. 指示のない候補には触らない.

1. 生成時の作業ディレクトリ (`_tmp/work_<対訳ファイル名から .md を除いた
   もの>` など) に `source.txt` が残っていれば, 置換の前に
   `scripts/verify_taiyaku.rb <source.txt> <md>` を実行して出力を控える
2. 旧表記を統一先に置換する. 旧表記が別の語の一部になっていないかを
   先に検索し, 巻き込む場合は照合する文字列を広げる. 日本語を含む
   `ruby -e` には `LC_ALL=en_US.UTF-8` を付ける
3. 漢訳名だけで書いた箇所は, 1 箇所ずつ文脈を見て直す
4. メタ情報を更新する
   - frontmatter の `updated`: 変更したファイルだけ作業日にする
   - `### Meta` ブロックと `status: incomplete` の行は変えない
   - `_history.md` は更新しない (あるファイルにも追記せず, ないファイルにも
     新設しない)
   - `docs/translation_terms.md` には, ユーザの指示がない限り項目を足さない

## 手順 5: 検証

- 文脈付きの diff を全部読む. 変更が語釈行 (`*` で始まる行) と文訳
  (`→` で始まる行) だけで, パーリ再掲行と原文ブロックが変わっていない
  ことを確かめる
- 旧表記が対象ファイルに残っていないこと, 統一先の件数が置換前の合計と
  合うことを確かめる
- 同じ名前が 2 回続く形 (「新、新」「新（新）」など) がないことを確かめる
- 手順 4 の 1 で控えた `verify_taiyaku.rb` の出力が, 置換後も同じである
  ことを確かめる. `source.txt` がない場合は, パーリ再掲行に差がない
  ことの確認で代える

## 手順 6: 報告

- 変更したファイルと, 節ごとの変更箇所 (旧表記 → 統一先)
- 検証の内容と結果
- 直さなかった候補や, 報告だけにした点
- コミットとステージは行わない. ユーザの明示的な指示を待つ
