# 用例 (yorei) の作成

パーリ語句の用例を, 辞書の用例欄のように「出典 (原文)」+「訳」の形で並べる.
原文の抽出と出典の特定は scripts/yorei.py で決定論的に行い, 訳だけをこの
セッションで書く. 対訳の新規生成 (taiyaku) や既存対訳の改訂ではない.

引数: $ARGUMENTS

## 用例の範囲

- ユーザが文や箇所を指定したら, その文だけを用例にする. 他の経や律に同じ
  語句があっても出さない. 指定が「MN 79 の antarāyamakāsi」のように
  経と語なら, その経の中の該当文だけを出す
- 他の文脈の用例を出すのは, ユーザが「他の用例も」「他の文脈でも」と
  求めたときだけ. そのときも cscd-text MCP の検索結果を全部並べず,
  構文や語義の違いが分かる代表例に絞り, どの範囲を検索したかを一言添える
- 迷ったら少なく出す. 足りなければユーザが追加を求める

## 出力書式

1 用例につき 2 行. 出典と原文を 1 行目に, 日本語訳を 2 行目に 「」 で書く.

```
MN 79 (VRI §272) (nanu evaṃ sante tassa purisassa appāṭihīrakataṃ bhāsitaṃ sampajjatī ti)
「そうであるなら, その男の発言は根拠のないものということになるのではないか」

Vism VIII (VRI §223) (phuṭṭhaphuṭṭhokāse pana satiṃ ṭhapetvā bhāventass' eva bhāvanā sampajjati)
「しかし, (息が) 触れるその都度の箇所に念を据えて修習する者にこそ, 修習は成就する」

Dhp-a (ad Dhp 116, Cūḷekasāṭakabrāhmaṇavatthu) (dandhañ hi karoto ti yo pana ‘‘dassāmi, na dassāmi, sampajjissati nu kho me, no’’ti evaṃ cikkhallamaggena gacchanto viya dandhaṃ puññaṃ karoti)
「『ぐずぐずと (福徳を) なす者には』とは, 『与えようか, 与えまいか, 私に (この施しは) うまくいくだろうか, いかないだろうか』と, このように泥道を行く者のようにぐずぐずと福徳をなす者 (のことである)」
```

- 出典は VRI の段落番号で示す. 経典は `MN 79 (VRI §272)`, `DN 9 (VRI §425)`,
  註は `Ps (ad MN 79, VRI §272)`, `Sv (ad DN 9, VRI §423)`, 復註は
  `Ps-pṭ (ad MN 79, VRI §272)`, 清浄道論は `Vism VIII (VRI §223)`,
  Dhp 註は `Dhp-a (ad Dhp 116, <vatthu 名>)`. AN は段落番号が経番号と同じ
  なので `AN 4.127` だけでよい. SN は `SN 56.46 (VRI §1116)` の形
- PTS の巻・頁はユーザが求めたときだけ付ける. スクリプトが出す PTS 頁は
  XML の頁マーカーから取った推定で行番号がないため, DoP など辞書の記載で
  確認できたものだけを「M II 33,19」の形で使う. 未確認なら書かない
- 原文は DoP の引用スタイルで書く. 語句を含む最小限の節を引き (文頭の
  呼びかけや「taṃ kiṃ maññasi」などは落としてよい), 引用符 ‘‘ ’’ は外し,
  引用の ti は前の語と離して書く (sampajjatī ti), 母音脱落の連声は
  アポストロフィで示す (bhāventass' eva). 註の見出し語の ti も離す
  (dandhañ hi karoto ti). 異読注 [..] は入れない
- 訳は引いた範囲だけを訳す. 補った語は ( ) に入れる. 読点は ", " を使い
  「、」「。」は使わない (プロジェクトの表記に合わせる)
- 註の釈 (Ps などの語義説明) はユーザが求めたときだけ添える. 添えるときは
  原文の後に DoP 風に「; Ps III 273,10 : ...」とするか, 別の用例として
  `Ps (ad MN 79, VRI §272) (...)` の行を立てる
- 複数の用例は経蔵 (DN, MN, SN, AN, KN), 律蔵, 論蔵, 註, 復註, Vism の順に
  並べる
- 回答は本文に書く. notes/ への保存はユーザが指示したときだけ行う

## 手順 1: 出典ファイルの特定

ユーザが箇所を指定している場合は, その経・註の XML だけを対象にする
(既存対訳の frontmatter の source や, 対訳ファイルの Ref から分かる.
MN なら s0201m / s0202m / s0203m の 3 巻のどれか). cscd-text MCP
(`search_cscd_texts`) で全蔵を検索するのは, 他の文脈の用例を求められた
ときだけ. 結果の `[s0202m.mul.xml ]` のようなファイル名が `--code` に渡す
コードになる (`.xml` はあってもなくてもよい). 註は `s0202a.att`, 復註は
`s0202t.tik`.

既に _tmp/ にある XML だけを探すなら `--all-cached` でよいが, これも
指定箇所以外の一致を拾うので, 出力から指定箇所だけを選ぶ.

## 手順 2: 抽出

```bash
python3 scripts/yorei.py --code s0202m.mul 'appāṭihīrakataṃ bhāsitaṃ sampajjat'
```

- 1 一致につき 2 行出る. 1 行目が出典の引用形 (そのまま用例の出典に使える)
  と, 角括弧内にファイル名 / 見出しの連鎖 / VRI 段落番号 / PTS 頁 (推定).
  2 行目が一致を含む文
- 分割ファイルは 404 になるまで順に tipitaka.org から取得し _tmp/ に
  キャッシュする. 初回は時間がかかる (AN の 1 集で 30-50 ファイル)
- `--xml _tmp/e0101n.mul8.xml` でローカルファイルを直接指定できる
- `--para` で段落全体, `--keep-notes` で異読注つき, `-i` で大小無視
- 文の切り出しは句読点に基づく簡易なもの. 偈や長い複文では前後が欠ける
  ことがあるので `--para` で段落を見て必要な範囲を自分で決める

## 手順 3: 書式化と訳

スクリプトの出力から用例に使う範囲を選び, 上の書式に整えて訳を付ける.
原文の文字列はスクリプト出力から取り, 自分で打ち直さない (連声の
アポストロフィと ti の分離だけを加える).

## 出典略号の対応範囲と注意

- DN / MN / SN / AN とその註・復註, Dhp / Dhp-a, Vism / Vism-mhṭ に対応.
  それ以外 (律蔵, 論蔵, 他の KN) はファイル名と見出し連鎖だけが出るので,
  引用形は見出しから自分で組む
- SN の経番号は相応内の vagga 番号 x 10 + 経番号で推定している. vagga が
  10 経でない相応 (SN 35 など) ではずれるので, 角括弧内の見出し
  (「6. Andhakārasuttaṃ」など) と照合する
- MN の経番号は巻ファイルと vagga 番号から計算している. 対応表は
  scripts/yorei.py の先頭にある
